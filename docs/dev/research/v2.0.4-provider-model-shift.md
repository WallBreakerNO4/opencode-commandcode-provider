# OpenCode 2.0.4 插件 API 变更：catalog 域 → provider/model 域

> 状态：已定稿。取证日期：2026-09-17。
> 环境：本机 `opencode v2.0.5`；npm `@opencode/plugin` 2.0.0–2.0.5 的 dist 类型；`anomalyco/opencode` tag `v1.18.30` 源码（用于核对 v1 宿主内嵌 runtime 的 API 世代）。
> 关系：本文是 [`v2-stable-contract.md`](./v2-stable-contract.md)（v2.0.1 取证）的后续——该文 §0 的 catalog 相关条目与差异表对应项自 2.0.4 起过时。插件侧适配随 0.2.0 发布（`src/host/v2.ts`）。
> 取证方式（全部只读）：npm registry tarball 类型对照、宿主二进制字符串、隔离真机（XDG 重定向 + dummy key）、官方 V2 插件文档。

## 0. 结论速览

1. **破坏性变更点**：宿主插件 API 的 `ctx.catalog` 域自 v2.0.4 起被移除，取代为 `ctx.provider` 与 `ctx.model` 两个域；`@opencode/plugin` 类型定义在 2.0.3 → 2.0.4 之间除域替换外无其他变化。2.0.0–2.0.3 的 `catalog` 域在 2.0.4+ 宿主上不存在，访问即 `TypeError`，插件加载失败（`state.status = failed`）。
2. **新旧域对照**：

   | catalog（≤ 2.0.3） | provider / model（≥ 2.0.4） |
   | --- | --- |
   | `ctx.catalog.transform(editor)` | `ctx.provider.transform(editor)`（注册 provider source + 模型清单）与 `ctx.model.transform(editor)`（活动模型集合的覆盖编辑） |
   | `editor.provider.update(id, …)`（update-or-create） | `editor.add({ info, models })`（source 注册，定义自包含）；`editor.update(id, …)` 编辑已有 provider |
   | `editor.model.update(providerID, modelID, …)`（宿主默认基线合并） | source 注册走 `add` 的 models 清单；编辑走 `editor.models.set / update / remove` |
   | `ctx.catalog.reload()` | `ctx.provider.reload()` / `ctx.model.reload()` |

3. **未变面**：`integration.transform`（域形状逐字未变）、`ctx.aisdk` 域、`aisdk:` 自指机制（前缀强制、`file://` 直载、工厂判据不变）、`Provider.Info` 与 `Model.Info` 的字段集（`activation` / `package` / `integrationID` / `settings`；模型的 `modelID` / `capabilities` / `limit` / `variants` / `cost` / `time` / `status` / `enabled` 均在）。
4. **v1 宿主内嵌 runtime 仍是 catalog 世代**：`v1.18.30` 的 `packages/plugin/src/v2/` 域集为 agent / aisdk / catalog / command / integration / plugin / reference / skill，无 provider / model；其 `setup` 调用被 `Effect.ignoreCause` 包裹（`packages/core/src/config/plugin/external.ts`），且 v1 功能由 `server()` config hook 先到协商（`src/host/v1.ts`）。插件对缺 provider 域的 ctx 安静退出（`src/host/v2.ts` 世代守卫）。
5. **最低宿主版本**：插件 v2 面自 0.2.0 起要求 OpenCode ≥ v2.0.4；安装指南与 README 已按此口径更新。

## 2. 运行时形状（v2.0.5 隔离真机）

setup 收到的 ctx 自有键：

```
app, location, options, agent, aisdk, command, event, experimental, generate,
model, provider, integration, mcp, permission, plugin, reference, rpc, skill,
storage, tool, vcs, websearch, worktree, session, shell
```

`catalog` 缺席；`provider` = `list / get / transform / reload`；`model` = `list / default / transform / reload`。

## 3. 插件侧适配与核对

- `src/host/v2.ts` 的 setup 迁移到 `provider.transform` + `editor.add({ info, models })`，模型数据变更回调走 `provider.reload()`；integration 接线保持不变。
- 适配后的隔离真机核对（dummy key，v2.0.5）：插件状态 active；44 个 `commandcode-go/*` 模型；`/api/provider` 的 `activation:"auto"` 与 `package:"aisdk:file://…/dist/index.js"`；`/api/integration` 的 key / env 方法与 label；`run` 到网关的 401（链路已通，非 model/provider not found）。
- 无凭证语义不变：provider 不可见、模型列表为空。
